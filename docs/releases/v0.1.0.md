## What's new (acceptance criteria summary)
- AC1-AC3: a new, uniquely solvable easy 9x9 puzzle (36-46 givens) on first launch.
- AC4-AC8: select a cell, enter digits 1-9, replace digits; givens are visually distinct and cannot be changed.
- AC9-AC11, AC20: mistakes (wrong vs the solution) are shown immediately with a non-colour cue; Erase clears a cell.
- AC12-AC14: "solved" message locks the grid; a full grid with mistakes is not solved; New Game gives a different puzzle.
- AC15-AC18: single-slot autosave; the game, mistakes and solved state survive relaunch and process death; a missing or invalid save falls back to a new puzzle without crashing.
- AC19: portrait only. AC21: TalkBack semantics. AC22: fully offline (no INTERNET permission). AC23: runs on API 26.

## Known limitations and carried items
- Security (0 Critical, 0 High, 0 Medium, 3 Low):
  - S-01: no Gradle wrapper jar or dependency verification metadata.
  - S-02: backup rules include the whole file domain rather than only the save file.
  - S-03: the `benchmark` variant is debug-signed. It must never be published.
- Manual checks NOT RUN: Accessibility Scanner (substituted by uiautomator bounds checks, a recorded deviation), GPU rendering bars, TalkBack spoken audio (the accessibility tree was verified, audio was not captured).
- Tap latency (100 ms target) was not quantified; device numbers come from an emulator (first launch median 722 ms, worst 1107 ms; restore overhead about 100 ms).
- Performance baseline is only proposed (`docs/perf/20261019-sudoku-mvp/proposed-baseline.json`, result NO_BASELINE accepted at G4.4). The owner promotes it through a `governance/*` PR.
- Follow-up: `TouchTargetTest` should use `boundsInRoot` with equal spacing; edge columns measure 36/44 dp (above the 24 dp cell minimum agreed in the spec).
- Governance flag for the owner: the T7 tester wrote scratch files via Bash heredoc after the Write tool was blocked by a hook.

## Install and build notes
- Requirements: JDK 17, Android SDK 36, device or emulator API 26+. Use the commands in `docs/project.md`.
- Release signing is environment-only (`SUDOKU_*` variables); no keys are in the repository. Without them a release build is unsigned.
- Publish only the `release` variant. Never publish the debug-signed `benchmark` variant (S-03).
- Store or production deployment is a manual owner action and is not part of this release.

## Upgrade and rollback
- Upgrade: none (first release).
- Data: no migration. The saved game uses format version 1 (ADR 0002); this is the first save format, so there is nothing to migrate or reverse.
- Rollback: revert the release PR on `main` (a new revert PR from a `governance/*` or `hotfix/*` branch), or reinstall the previous build. As no previous build exists for this product, rollback means uninstalling the app, which deletes the local save.
